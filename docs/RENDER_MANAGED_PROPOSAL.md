# Proposed Render-managed pilot

This is a reviewable alternative, not an approved ownership change or a live
deployment. The current main branch still selects OpenTofu as infrastructure
owner. Do not apply both methods to these services.

## Why propose it

The four tested images and GitHub CI are ready. The existing OpenTofu path still
needs a locked HTTP state backend and separate provider/state credentials in
GitHub Actions. No backend endpoint is configured. The AWS connection inspected
for an alternative needs reauthentication; no AWS resources were changed.

Render's Blueprint planning API can resolve the four-service topology and
generate service secrets without exposing their values in the repository or
chat. This alternative does not require a separate OpenTofu state service or
GitHub-to-Render API credential.

Region: Oregon. Workspace: Jim's, `tea-dbdccfpsrm7s73b8rugg`.
Use `existingResources:create_new` so no existing services are adopted or changed;
Render may append a unique suffix to the four names. Disable Blueprint auto-sync.

`deploy/render-pilot.proposed.yaml` uses the exact four immutable image digests
already tested and pinned in `deploy/release.json`. Runtime start commands derive
private URLs from Render service references, while AX's CSRF origin references
its own platform-provided HTTPS URL. Secrets are generated by Render and shared
only with the services that need them. The generated AX admin password must be
retrieved through the owner's secure service settings for human sign-in; never
print or commit it. The Computer remains restricted to the Git High hostname.

The initial proposal deliberately has **no database connection**. It does not
create or alter Moby Alpha's database, run live migrations, or claim that stored
profiles/audit history are persistent. Live REIGN database setup remains a
separate step requiring a verified restricted role and private connection.
Temporal's pilot workflow history uses its disk. Browser sessions are ephemeral.
External computer/full-desktop adapters remain unfinished.

## Before applying this alternative

1. Obtain James's explicit decision to use Render Blueprint ownership instead
   of OpenTofu for this pilot, and to launch the initial pilot without REIGN
   database persistence while the isolated schema/role are prepared.
2. Record that choice in AGENTS.md, HANDOFF.md and DEPLOYMENT.md; disable the
   OpenTofu apply path for these resources so there is only one owner.
3. Merge the reviewed configuration after required CI. Point the pending
   Blueprint to main and re-plan that exact revision with auto-sync disabled.
4. Inspect the resolved create-only plan and cost, then apply within the approved
   scope. Do not adopt Workmates, Git High, Moby Alpha or any other service.
5. Verify all four deploys and digests, authenticated readiness, actual live
   browser frames, takeover/handback and restart behavior. James's human test
   remains distinct from automated CI acceptance.

Subsequent releases still require CI and digest review. Render syncs must use
reviewed immutable digests; publishing an image must not silently deploy it.
If OpenTofu ownership is retained, leave this proposal unapplied and complete
the original protected HTTP-state and credential setup instead.
